# プロジェクト生成ルール

この文書は、Codex や Claude Code などの LLM が RecotteStudioMCP を利用し、Recotte Studio の `.ccproj` プロジェクトを生成・編集する際の規則を定めます。構造的に正しいファイルを作るだけでなく、台詞・字幕・立ち絵・画像・動画の役割を分け、見やすい解説動画を効率よく制作することを目的とします。

## 基本方針

- 制作開始時に `recotte_get_generation_rules` でこの文書を取得し、生成・編集時の判断に使う。

- Recotte Studio 本体が担う台詞のテロップ表示、対応する読み上げソフトとの音声連携、キャラクターの口パク・目パチを活用し、LLM が不要な素材を作らない。
- **Recotte Studio 本体の製品機能と、RecotteStudioMCP から操作できる機能を混同しない。** 本体が対応するキーフレーム・各種エフェクト・トランジション・動画書き出しを、MCP で直接実行できるとは限らない。
- 既存プロジェクトを編集する前に `recotte_inspect_project`、`recotte_get_capabilities`、必要に応じて `recotte_list_layers` と `recotte_list_timeline` で画面・字幕枠・話者・レイヤー・編集可否を確認する。取得した情報を推測より優先する。
- 映像効果は「何を見せ、何を理解してもらうか」を基準に選ぶ。常に動かすのではなく、静止させることも積極的に選択する。
- キャラクターや特定のテキストスタイルが必要なら、Recotte Studio で設定済みのプロジェクトをテンプレートとして利用する。未対応のキャラクター新規作成、未知のフィールドや音声合成操作を推測で行わない。
- 新しいプロジェクトにキャラクターを登場させるときは、キャラクターを配置済みのプロジェクトを `recotte_list_characters` で調べ、`importCharacter` で取り込む。登場させるキャラクターは全員を同じドナーから取り込む。字幕枠がキャラクターの配置に合わせて調整されているためである。

## 安全な保存

- 新規作成には RecotteStudio.Core の検証済み `1.8.5.0` 組み込みテンプレートを使用する。
- 通常検証に加えて、バージョン、日時、GUID、プロジェクト名、保存先 URI、画面設定、初期レイヤー、スタイルを検証する。
- Core の保存処理を利用し、UTF-8（BOM なし）、CRLF で同一ディレクトリの一時ファイルへ書き込む。
- 一時ファイルを再読み込みし、生成固有検証と意味的同一性確認に成功した場合だけ完成ファイルとして配置する。
- 検証に失敗した生成物や途中まで書かれたファイルを完成パスへ配置しない。
- 原則として `recotte_apply_operations_and_save_copy` などで別名保存する。上書きが必要な場合は、MCP のバックアップ・外部変更検出を伴う操作を使用する。手作業で `.ccproj` の未知の構造を書き換えない。
- 保存前には対応するプレビューを使い、保存後は `recotte_validate_project` の診断結果を確認する。

## 音声

Recotte Studio は対応する入力文字読み上げソフト（例: VOICEPEAK、CeVIO AI など）と連携して音声を挿入できます。音声合成ソフトおよび話者の設定は Recotte Studio 側に必要です。**MCP 自身が音声を合成するわけではありません。**

- LLM は**台詞の読み上げ音声ファイルを別途生成しない**。台詞は音声素材を持たない `Speaker Voice` として配置し、読み上げ音声の生成・調整は Recotte Studio と連携ソフトに任せる。
- 台詞の表示用テキストと読み上げ音声を別々の素材として二重管理しない。
- BGM・効果音・環境音など、台詞以外の音素材はこの禁止対象ではない。
- 新規のテキストのみの `Speaker Voice` は `audio` を持たせず、`properties.File.p-value` は空文字列、`voice-hash` は `0` とする。音声用項目を `file-items` に追加しない。
- 既に音声を持つ `Speaker Voice` の本文を変更した場合、古い音声は残る。`RC4208` / `audioRegenerationRequired` が示す対象は、Recotte Studio 上での音声再生成が必要と利用者へ伝える。

## 字幕・テロップと画面配置

Recotte Studio は話者のコメントを所定の位置にテロップ表示できます。台詞のテロップは Recotte Studio に任せ、画像・動画素材に同じ台詞を焼き込まない。

- **字幕枠の実座標を最優先する。** `recotte_get_capabilities` から画面サイズと各 `Speaker` レイヤーに対応する Telop Frame の範囲を調べ、表示される字幕と重要情報が重ならないようにする。
- 字幕枠が取得できず、字幕を表示する想定なら、画面**下側 20%** を暫定的な字幕領域とする（1920×1080 では下から 216px）。これは固定仕様ではなく代替のレイアウト指針である。
- 字幕領域へ、顔、主題となる被写体、読ませたい文字、図表の主要部分を置かない。背景画像を画面全体に敷くこと自体は問題ない。
- 字幕の背後は読みやすさを優先し、密な模様、強い明暗変化、激しい動きを控える。字幕が読みにくければ、背景の構成・トーンを調整する。
- 図のラベル、タイトル、コード片、説明の見出しは画像に含めてよい。ただし、**話者が読む台詞そのものを画像へ描画しない**。
- 実際にテロップ表示を無効にしている台詞・構成では、字幕が必ず現れると仮定しない。立ち絵・注釈など、ほかの重なりも考慮する。

## 台詞の分割と時間設計

- 1 つの台詞が 60 文字以上になる場合は、読みやすい長さに分割する。
- 句点、文の区切り、意味のまとまりを優先して分割する。
- 分割後の順序と本文を保持し、連結したときに元の台詞と一致させる。
- 分割した各台詞の `name`、`text.text`、`text.stext[].text` を同じ内容にする。
- 話すテンポと理解に必要な時間を考慮して表示時間を設定する。音声生成前の台詞時間は暫定値であり、読み上げの長さ・間合いを Recotte Studio で最終調整する余地を残す。
- 説明する図や操作画面は、対応する台詞に合わせて表示する。図表・コード・比較表は視聴者が読めるだけの時間を確保し、必要なら段階的に見せる。

## 静止画と動画素材の選択

| 素材の使い方 | 適した場面 | 方針 |
| --- | --- | --- |
| 静止画のまま配置 | コード、比較表、設計図、文字の多い図解 | 読みやすさを優先し、動かさない |
| 1 枚の画像を動画化 | 背景、風景、イラスト、注目対象の提示 | 緩やかなズームやパンで視線を誘導する |
| 複数画像を動画化 | 段階的な説明、状態変化、簡単な動作表現 | 連続画像の切り替え時間と繰り返しを調整する |

- 静止画を長く見せるだけでは単調になる場面では、MCP の動画化機能を検討する。ただし、意味のない動きは付けない。
- 背景や挿絵はプロジェクトの画面比率に合わせ、意図しない切り抜きや余白を避ける。重要な要素を字幕や立ち絵が隠さないようにする。
- 画像や動画に字幕の台詞を焼き込まない。解説に不可欠な文字は、字幕とは独立した説明要素として扱う。

## MCP による静止画の動画化

### 1 枚の画像をズーム・パンする

`recotte_create_video_from_image` を使用する。背景、風景、イラストに緩やかな動きを加えるための手段とする。

- `motion` は `none`、`zoomIn`、`zoomOut`、`panLeft`、`panRight`、`panUp`、`panDown` から選ぶ。
- `zoomIn` は注目対象への視線誘導、`zoomOut` は全体像への切り替え、`pan*` は対象を順に見せる場面に用いる。パンの向きは**視点が移動する向き**であり、画像自体の移動方向とは逆になることに注意する。
- 説明動画では `easing: easeInOut` を基本とし、控えめな動きなら倍率 1.05～1.15 程度を目安とする。ツールが許容する倍率は 1.05～1.5。
- `focusX` と `focusY` を調整し、顔や重要な対象が字幕領域へ移動しないようにする。
- `fit: cover` は画面を埋めるが画像が切り抜かれうる。`fit: contain` は全体を見せるが余白が生じる。用途に合わせて選択する。
- 生成動画の長さ `duration` は 0.5～60 秒。長い場面は必要に応じて素材・カットを分ける。

### 複数画像からパラパラアニメを作る

`recotte_create_flipbook_video` を使用する。

- 連続した絵や工程の変化を順に見せるときに使う。画像のサイズ・被写体の位置・背景の統一感を意識する。
- `frames` を表示順に指定し、`frameDuration` や画像ごとの `duration`、`loops` で速度と繰り返しを調整する。
- 最大 600 フレーム指定、異なる画像は 200 枚まで、`loops` は 1～100。繰り返しを含む総時間は 60 秒以内。
- `fit` の既定値は `contain`、余白・透過部の背景色の既定値は白。必要に応じて変更する。
- ツールの返す各フレームの開始時刻・長さを参照し、台詞と画面上の変化を対応させる。ループの継ぎ目で不自然に飛ばないか配慮する。

### 動画化ツール共通の条件と配置

- 現行の動画化機能は **1920×1080 のプロジェクトのみ**に対応し、外部の `ffmpeg` が必要。MCP の設定画面か PATH で利用できるようにする。
- MP4（H.264 / AAC）を生成する。生成される音声トラックは無音であり、読み上げ音声の代わりではない。
- ツールは静止画や元の `.ccproj` を変更しない。**動画を生成しただけではタイムラインに配置されない。**
- 戻り値の `suggestedOperation`（`addVideoObject`）を利用し、配置先に合わせて `start` / `end` を設定したうえで、`recotte_apply_operations_and_save_copy` などで保存する。
- ワイプや画面の重ね合わせなど、同じ時間に2本の動画を表示する場合は、`addVideoLayer` で Video レイヤーを追加し、そのレイヤーに配置する。追加したレイヤーは既存の動画より手前、話者・注釈レイヤーより奥に描画される。追加すると後ろのレイヤーの番号が1つずつずれるため、同じ操作内では `layerName` で名前を付け、レイヤーを名前で指定する。
- `MCP_FFMPEG_UNAVAILABLE` のときは設定不足を利用者に伝える。勝手に未検証の別の動画化手段へ置き換えず、必要なら静止画での代替を提案する。
- 動画化した素材が Recotte Studio 本体で正しく再生・書き出しできたかは、`.ccproj` の構造検証とは別に確認する。

## 図形・エフェクトの利用

- 矢印、記号、漫符などの図形は `recotte_list_figures` で確認し、`placeable` なものに限り `addFigureObject` で配置する。
- MCP で編集できる画像・動画のフェードは `Alpha Fade` / `Alpha Fade Out`。`recotte_list_effects` の `editable` と、`recotte_list_object_effects` の結果を確認する。
- Recotte Studio 本体は多様なエフェクト、トランジション、キーフレーム編集に対応するが、**MCP での操作対応とは別**である。列挙できるだけのエフェクトを編集可能と解釈しない。
- 演出は要点、場面転換、説明上の区切りなど意味がある場合に付ける。情報を読む邪魔になる演出を避ける。

## 検証と完了報告

1. 事前にプロジェクトのバージョン、Capabilities、画面サイズ、字幕枠、レイヤー、話者、タイムラインを調べる。
2. 台詞・画像・動画・図形を設計し、字幕との重なりや表示時間を確認する。
3. 必要に応じて静止画の動画化ツールを実行し、生成した MP4 をタイムラインへ配置する。
4. 対応するプレビューツールで操作と保存結果を確認し、安全に保存する。
5. `recotte_validate_project` のエラーを解消し、警告を確認する。

`RC2401` は、字幕枠が描画される間、画面全体を埋めない Image / Video が表示される場合の**レイアウト警告**である。画像内の文字と字幕の重なりを万能に検出するものではない。小さな図や挿絵を意図的に配置した場合は、警告を消すためだけに画面全体へ拡大しない。

完了報告では、生成・編集したプロジェクト、追加した動画素材、検証結果、音声再生成の必要性、Recotte Studio 本体での未確認事項を区別する。MCP の処理だけで本体を起動・再生・動画書き出ししたと主張しない。
